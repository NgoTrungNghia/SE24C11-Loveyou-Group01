### RETROSPECTIVE DETAILS

| Discussion Topic | Content |
| :--- | :--- |
| **What went well?** | - The team organized PA4 work around requirements revision, software architecture, implementation and submission evidence.<br>- Architecture work was reviewed against the actual frontend/backend/database structure instead of being documented independently from the source code.<br>- The team followed the required Spec Kit workflow for the selected PA4 functional groups. |
| **What went wrong?** | - Architecture documentation required several consistency checks because the Level 1, Level 2 and Level 3 diagrams had to remain aligned with the implementation.<br>- Some implementation and documentation tasks competed for the same time near the end of the sprint|
| **Problems & Root Causes?** | - Some tasks were initially estimated mainly from the document-writing effort and did not fully account for source-code verification and integration time.<br>- The two PA4 functional groups required coordination across frontend, backend and database work, which created dependencies between team members.|
| **Action Items for Improvement?** | - Confirm the exact scope of each functional group before implementation starts.<br>- Create architecture diagrams from the current source code and update them immediately when the implementation changes.<br>- Add evidence collection tasks to the sprint backlog from the beginning rather than at the end. |
| **Lessons Learned?** | - Architecture documentation must be maintained together with implementation, not written only at the end <br>- Spec Kit artifacts should be treated as part of the deliverable, not as optional development notes |
